## Important

1. **Preview-only publication accepts no usable preview.** `ruoyi-modules/mju-showroom/src/main/java/com/mju/showroom/service/virtual/VirtualShowroomValidationService.java:35` only checks `hasNonNull("previewRef")`, while `VirtualShowroomService.java:207` intentionally permits an empty reference in a draft. Binding with `previewRef: ""` sets a matching preview version in `VirtualScreenBindingService.java:38`, so this screen passes publication without an image. A nonimage resource key also passes because reference validation only checks membership, not image kind/MIME. Public sessions omit executable resources for preview-only screens (`VirtualResourceSessionService.java:50`), leaving these published screens unusable. Require a nonblank reference to an available supported image at publish time; retain permissive incomplete-draft behavior separately.

2. **Rebinding certifies an old preview as the new instance without regeneration.** `ruoyi-modules/mju-showroom/src/main/java/com/mju/showroom/service/virtual/VirtualScreenBindingService.java:38` copies any owned `previewRef` from the request and assigns the newly selected instance's version. `VirtualShowroomValidationService.java:36` then checks only that numeric version. An update from instance A to B with A's image is accepted as version-matched; ordinary draft save can also rewrite `previewInstanceVersion`. This breaks the required regenerate-preview-before-republish flow. Record trusted preview provenance against the binding's instance/artifact identity when the preview is produced/registered, verify it during publication, and do not relabel an existing image merely because a bind request supplies its key.

3. **Cancellation loses the QUEUED-to-RUNNING race and can allow a late success.** `ruoyi-modules/mju-showroom/src/main/java/com/mju/showroom/service/virtual/VirtualModelImportService.java:43` reads the job state, updates with exactly that old state, ignores the affected-row count, then returns success after cancelling the future. If the executor changes QUEUED to RUNNING between the read and update, the database never becomes CANCELLED. The task can become FAILED, or if conversion has already returned, continue into registration and satisfy the RUNNING check at `:68` and RUNNING-to-SUCCEEDED update at `:72`; that registration path has no interrupt check. Cancel atomically from either active state, inspect the outcome, and persist cancellation before relying on interruption so late-result registration reliably fails.

4. **Rollback can republish a template whose usage authorization has been revoked.** `ruoyi-modules/mju-showroom/src/main/java/com/mju/showroom/service/virtual/VirtualShowroomPublishService.java:23` checks showroom ownership and revision membership but immediately switches ONLINE. Ordinary publish explicitly calls `validation.authorizeSnapshot` at `:17`. After a template entitlement is removed, normal publication is denied, yet rollback to a historical revision containing it opens new public sessions. Recheck snapshot template authorization before the rollback pointer transaction, then recheck the relevant snapshot/room identity under lock. Preserve the existing lease policy for already-issued sessions.

## Minor

- `ruoyi-modules/mju-showroom/src/main/java/com/mju/showroom/service/virtual/VirtualTemplateRuntimeResourceService.java:32`–`:34`: bootstrap is inserted after the first literal `<head>` match, not necessarily before the first executable script. A script before an explicit head tag executes first, and a head-looking string in a comment can attract the insertion. Use an HTML-aware injection point guaranteed to precede executable content, or reject unsupported HTML structure during materialization. Typical generated Vite HTML satisfies the current assumption, but that assumption is not validated.
- `ruoyi-modules/mju-showroom/src/main/java/com/mju/showroom/service/virtual/VirtualShowroomPublishService.java:14`, `:25`: replaying an old request ID always reports `status: ONLINE` even if the room is now offline or points to another revision. This does not change the pointer, but the response can misrepresent current state. Distinguish the original operation result from the current publication state.
