Root ifcProvider.input returned sourceFile/entryHash/sourceHash and analyze/convert payloads spread the full source object. A bridge validates exact top-level keys per contract and correctly forbids parent entryHash. Every job would have returned IFC_INVALID_REQUEST before OpenModel. ### Important 2 — UI axis alias rejected all confirmed IFC imports (fixed)

A validateIfcOptions initially accepted only uppercase Y_UP/Y-UP/Y. The existing common/UI/Java protocol sends axis y-up, so otherwise-valid conversion requests would fail IFC_INVALID_OPTIONS before native parsing. A now checks string type then uppercases and normalizes the hyphen, accepting y-up while still allowing only Y_UP/Y. Z-up remains rejected. Reviewed metadata/ifcSource.js around line 135; current hash matches A's locked announcement.

### Minor — URI substring falsely dropped permitted SecurityRating (fixed)

Blocked properties and blocked groups emit fixed omitted diagnostics, preventing silent rejection/mismatch against C registration validation.
